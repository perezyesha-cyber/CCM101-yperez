# Laboratory 07 – Mission Reflection

In this laboratory activity, I learned that monitoring is important for keeping servers and applications working properly.

First, checking the host server's resources is important even if the containers are running perfectly. Containers still depend on the host's CPU, memory, disk space, and network. If the host runs out of resources, applications may become slow or stop working. Checking these resources helps prevent problems before they affect users.

Second, the `docker logs` command can help solve login problems by showing messages and errors generated by the application container. For example, the logs may show failed requests or application errors that help explain why a user cannot log in. By examining these messages, an administrator can investigate the cause and decide what to check next.

Third, logs and metrics provide different kinds of information. Logs show events, requests, and errors, such as the successful HTTP 200 requests and the HTTP 404 error generated during this activity. Metrics show numerical measurements, such as CPU percentage, memory usage, and network activity. Logs help explain what happened, while metrics help show how the container is performing.

Fourth, large companies can use monitoring tools such as Prometheus and Grafana to monitor thousands of containers. Prometheus collects and stores metrics from different systems, while Grafana presents the data in dashboards and graphs. These tools help administrators identify unusual resource usage and investigate performance problems across many containers.

Finally, this activity improved my ability to troubleshoot Linux environments. I practiced using terminal commands, deploying an Nginx container, sending HTTP requests, checking application logs, and monitoring resource usage. I also learned that it is important to examine both logs and metrics instead of guessing when a problem occurs. These skills can help me manage applications and solve technical problems more effectively in future cloud computing activities.

Overall, this laboratory activity helped me understand the responsibilities of a Cloud Operations Engineer and the importance of observing system health.
